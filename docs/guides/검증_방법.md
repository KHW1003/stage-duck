# 검증 방법 — 만든 것별로 해 보는 것

> CLAUDE.md 11장에서 옮겨 온 표다. 일을 마치고 검증할 때 **자기가 만든 것에 해당하는 줄만** 읽고 한다.

| 만든 것 | 해 보는 것 | 맞는지 보는 방법 |
|---|---|---|
| 수용 기준 | 그 AC의 Given-When-Then을 그대로 재현한다 | AC 문장과 결과를 한 줄씩 나란히 적는다 |
| 계산 (이용료, 위약금, 검사 시간) | `시연_예시값.md`의 값 + 경계 값(0원, 1원, 나머지가 생기는 금액, D-3/D-2 경계 시각) + 무작위 값 1,000건 이상 | 계산식을 그 자리에서 따로 써서 비교한다 (같은 함수를 다시 부르지 않는다). 불일치 0건이어야 한다 |
| 입력을 받는 API | 잘못된 값 수백 건: 빈 값, 음수, 501, 글자, `null`, 너무 긴 글, 지난 날짜 | 모두 `400 VALIDATION_FAILED`이고 `fieldErrors`의 칸 이름이 맞는지 본다 |
| 권한 | 다른 역할(방문자·사용자·심사 중 업체·승인 업체·관리자), 다른 사용자로 같은 요청 | 남의 것은 `404`, 역할이 안 맞으면 정해진 코드. 연락처가 응답에 없는지 본다 |
| 상태 변경 | 허용된 전이 모두 + 허용되지 않은 전이 몇 개 | 허용 안 된 것은 `409 INVALID_STATE`, `status_histories`에 한 줄씩 남는지 본다 |
| 동시·중복 요청 | 같은 요청 2개를 동시에, 같은 `Idempotency-Key`로 두 번 | 한 번만 반영되는지 DB 행 수로 센다 (MariaDB에서) |
| 마이그레이션 | 로컬 MariaDB에서 upgrade → downgrade -1 → upgrade | 세 번 모두 성공, `alembic heads`가 하나 |
| 화면 | 서버를 켜고 단계마다 값을 넣는다: 정상 값, 오류 값, 새로 고침, 모바일 폭(375px) | 단계마다 제목, 버튼 글자와 켜짐 여부, 오류 문구, 시뮬레이션 배너를 적는다 |
| 관리자 액션 | `/admin`에서 직접 눌러 본다 | 서비스 함수의 결과(상태·이력·경고 수)가 DB에 맞게 남는지 본다 |
