# 로컬 개발 환경 세팅 (처음부터 끝까지)

STAGE DUCK을 내 컴퓨터에서 실행하고 개발을 시작하기까지의 전 과정이다. **위에서부터 순서대로** 따라 하면 된다. 다 끝나면 맨 아래 체크리스트로 자기 세팅 이슈(#14 세환, #15 해원, #16 채은, #17 목산)를 닫는다.

- 기준: **Windows 10/11**. macOS는 괄호 안에 따로 적었다.
- 걸리는 시간: 처음이면 1시간 정도.
- 막히면 맨 아래 **"자주 나는 오류"**를 먼저 보고, 그래도 안 되면 내 세팅 이슈에 **오류 메시지를 복사해서** 댓글로 남긴다. **비밀번호와 `.env` 내용은 절대 적지 않는다.**

## A. 설치할 프로그램

이미 있으면 버전만 확인하고 넘어간다. 확인은 **PowerShell**(시작 메뉴에서 "PowerShell" 검색)에서 한다.

| 프로그램 | 버전 | 받는 곳 | 확인 명령 |
|---|---|---|---|
| Git | 최신 | https://git-scm.com/download/win | `git --version` |
| Python | **3.12.x** | https://www.python.org/downloads/ | `python --version` |
| Node.js | **22 LTS** | https://nodejs.org/ (LTS 버튼) | `node -v`, `npm -v` |
| MariaDB | **11.4** | https://mariadb.org/download/ (11.4 선택, Windows MSI) | `mysql --version` |
| VS Code | 최신 (권장) | https://code.visualstudio.com/ | |
| GitHub CLI | 최신 (선택) | https://cli.github.com/ | `gh --version` |

### 설치할 때 꼭 체크할 것

**Python**
- 첫 화면 아래쪽 **"Add python.exe to PATH"**를 반드시 체크한다. 안 하면 `python` 명령을 못 찾는다.
- 3.13이나 3.14가 아니라 **3.12**를 설치한다 (CI와 같은 버전).

**MariaDB (Windows MSI)**
- **root 비밀번호**를 정하는 화면이 나온다. 직접 정하고 **나만 아는 곳에 적어 둔다.** (팀원·Claude에게 알려 주지 않는다.)
- "Use UTF8 as default server's character set"을 체크한다.
- 포트는 기본값 **3306** 그대로 둔다.
- 함께 설치되는 **HeidiSQL**은 DB를 눈으로 보는 프로그램이다. 써도 되고 안 써도 된다.
- 설치가 끝나면 `mysql` 명령이 PATH에 없을 수 있다. 그때는 C단계의 "명령으로 접속이 안 되면"을 본다.

> (macOS) `brew install python@3.12 node@22 mariadb@11.4` → `brew services start mariadb@11.4`
>
> (Docker가 있는 사람) MariaDB를 설치하지 않고 저장소 폴더에서 `docker compose up -d mariadb`로 띄워도 된다. 이때 DB·계정은 이미 만들어져 있다 (DB `stageduck`, 계정 `stageduck`, 비밀번호 `stageduck`). C단계를 건너뛰고 D단계로 간다.

## C. MariaDB 데이터베이스 만들기

우리 서비스가 쓸 **DB 하나**와 **계정 하나**를 만든다. root 계정은 이 단계에서만 쓰고, 앱은 `stageduck` 계정으로 접속한다.

1. MariaDB에 root로 접속한다.

```powershell
mysql -u root -p
```
root 비밀번호를 입력하면 `MariaDB [(none)]>`가 나온다.

2. 아래를 **그대로 복사해서** 붙여 넣는다. `여기에_비밀번호`만 내가 정한 비밀번호로 바꾼다 (root와 다른 것을 추천, 이 비밀번호는 D단계의 `.env`에 쓴다).

```sql
CREATE DATABASE stageduck CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'stageduck'@'localhost' IDENTIFIED BY '여기에_비밀번호';
GRANT ALL PRIVILEGES ON stageduck.* TO 'stageduck'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

3. 새 계정으로 접속되는지 확인한다.

```powershell
mysql -u stageduck -p stageduck
```
비밀번호를 넣고 `MariaDB [stageduck]>`가 나오면 성공. `EXIT;`로 나온다.

### (선택) 테스트를 MariaDB로도 돌려 보고 싶은 사람
평소 `pytest`는 DB 설정 없이 임시 SQLite로 돈다. CI처럼 MariaDB로 돌리려면 테스트용 DB를 하나 더 만든다 (root로 접속해서).

```sql
CREATE DATABASE stageduck_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
GRANT ALL PRIVILEGES ON stageduck_test.* TO 'stageduck'@'localhost';
FLUSH PRIVILEGES;
```

### 명령으로 접속이 안 되면
- `mysql`을 찾을 수 없다고 나오면 전체 경로로 실행한다: `& "C:\Program Files\MariaDB 11.4\bin\mysql.exe" -u root -p` (PowerShell). 또는 시작 메뉴에서 **"MariaDB 11.4" → "Command Prompt (MariaDB 11.4 (x64))"**를 열고 거기서 `mysql -u root -p`를 한다.
- 또는 **HeidiSQL**에서 root로 접속한 뒤 "쿼리" 탭에 위 SQL을 붙여 넣고 실행(F9)한다.

## D. 백엔드 실행 (FastAPI)

모든 명령은 **`backend` 폴더 안에서** 한다.

### D-1. 가상 환경 만들기 (처음 한 번)

```powershell
cd C:\projects\stage-duck\backend
python -m venv .venv
.venv\Scripts\Activate.ps1
```
줄 앞에 **`(.venv)`**가 붙으면 성공. 앞으로 백엔드 명령은 항상 `(.venv)`가 붙은 창에서 한다.

> PowerShell에서 "이 시스템에서 스크립트를 실행할 수 없으므로…" 오류가 나면 I단계의 1번을 본다.
> (Git Bash) `source .venv/Scripts/activate` · (macOS) `source .venv/bin/activate`

### D-2. 패키지 설치

```powershell
python -m pip install --upgrade pip
pip install -r requirements-dev.txt
```

### D-3. 설정 파일 `.env` 만들기

```powershell
copy .env.example .env
```
(macOS: `cp .env.example .env`)

`backend\.env`를 VS Code로 열어서 두 줄을 고친다.

```
APP_ENV=local
DATABASE_URL=mariadb+pymysql://stageduck:C단계에서_정한_비밀번호@localhost:3306/stageduck?charset=utf8mb4
ADMIN_SESSION_SECRET=아래_명령으로_만든_긴_문자열
```

`ADMIN_SESSION_SECRET`에 넣을 값은 이 명령으로 만든다 (나온 글자를 그대로 복사).

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

- 비밀번호에 `@`, `:`, `/`, `#` 같은 기호가 있으면 주소가 깨진다. 기호 없는 비밀번호를 쓰거나 C단계에서 비밀번호를 바꾼다.
- **`.env`는 절대 커밋하지 않는다** (`.gitignore`에 들어 있다). 저장소 맨 위의 `.env.example`이 아니라 **`backend\.env.example`**을 복사해야 한다.
- (Docker로 MariaDB를 띄운 사람) 비밀번호 자리에 `stageduck`.

### D-4. 테이블 만들기

```powershell
alembic upgrade head
```
마지막 줄에 `Running upgrade  -> 0001, ...`이 나오면 성공. (이미 최신이면 아무것도 안 나와도 정상이다.)

### D-5. 관리자 계정 만들기 (처음 한 번)

```powershell
python -m app.cli create-admin --email admin@stageduck.test
```
관리자 비밀번호(8자 이상)를 묻는다. 입력할 때 글자가 안 보이는 것이 정상이다.

> Git Bash에서는 비밀번호 입력에서 멈출 수 있다. 이 명령은 **PowerShell**에서 한다.

### D-6. 테스트 돌리기

```powershell
pytest -q
```
`16 passed`처럼 나오면 성공 (숫자는 개발이 진행되면 늘어난다). 이 테스트는 DB 설정 없이 임시 SQLite로 돈다.

(선택) MariaDB로 돌리기:
```powershell
$env:TEST_DATABASE_URL="mariadb+pymysql://stageduck:비밀번호@localhost:3306/stageduck_test?charset=utf8mb4"
pytest -q
Remove-Item Env:TEST_DATABASE_URL
```

### D-7. 서버 켜기

```powershell
uvicorn app.main:app --reload
```
브라우저에서 확인한다.

| 주소 | 보이는 것 |
|---|---|
| http://localhost:8000/api/v1/health | `{"status":"ok","env":"local","simulation":true}` |
| http://localhost:8000/docs | API 문서 (Swagger) |
| http://localhost:8000/admin | 관리자 화면 — D-5에서 만든 이메일·비밀번호로 로그인 |

끄기: 터미널에서 `Ctrl + C`.

## E. 프론트엔드 실행 (React)

**새 터미널**을 하나 더 연다 (백엔드 서버는 켜 둔 채로). 명령은 **`frontend` 폴더 안에서** 한다.

```powershell
cd C:\projects\stage-duck\frontend
npm install
npm test
npm run dev
```

- `npm install`: 처음과, `package.json`이 바뀌었을 때만.
- `npm test`: `5 passed`처럼 나오면 성공.
- `npm run dev`: http://localhost:5173 을 연다. 상단에 **"포트폴리오 시뮬레이션"** 배너가 보이면 성공.
- `npm run build`: PR을 올리기 전에 한 번 (타입 검사 포함).

프론트(5173)에서 `/api`, `/ws`, `/admin`으로 가는 요청은 자동으로 백엔드(8000)로 넘어간다. 그래서 **둘 다 켜져 있어야** 화면에서 API가 동작한다.

## G. Claude Code 준비

우리는 개발 대부분을 Claude에게 맡기고, **규칙은 저장소의 `CLAUDE.md`**가 정한다. Claude Code는 저장소 폴더에서 열면 `CLAUDE.md`를 알아서 읽는다.

1. Claude Code를 설치한다 (데스크톱 앱의 Code 탭, VS Code 확장, 또는 터미널 `claude` 중 편한 것).
2. **저장소 폴더(`C:\projects\stage-duck`)를 열고** 시작한다. 다른 폴더에서 열면 `CLAUDE.md`를 못 읽는다.
3. 읽을 것 (10분):
   - `CLAUDE.md` 3장(반드시 지킬 것), 5장(내 묶음의 담당 파일)
   - `docs/guides/클로드_사용법.md` (세션 쓰는 법)
   - `specs/tasks.md`에서 내 이슈 목록
4. 첫 메시지는 이렇게 시작한다.

> 이슈 #22, 1번 묶음. 이슈 내용대로 만들어 줘. 먼저 계획을 보여 줘.

- **이슈 하나 = 세션 하나.** 다른 이슈를 시작할 때는 `/clear`.
- Claude가 `.env` 내용이나 MariaDB 비밀번호를 물어도 알려 주지 않는다. 필요하면 내가 직접 `.env`를 고친다.
- Claude는 PR을 머지하거나 승인하지 않는다. 머지는 사람이 한다.

## H. 매일 개발할 때 하는 순서

### 일 시작할 때
```powershell
cd C:\projects\stage-duck
git switch develop
git pull
```
그다음 **바뀐 것에 따라** 한다.

| 바뀐 것 | 할 일 (폴더) |
|---|---|
| `backend/requirements*.txt` | `pip install -r requirements-dev.txt` (backend, `(.venv)`) |
| `backend/alembic/versions/`에 새 파일 | `alembic upgrade head` (backend) |
| `frontend/package.json` | `npm install` (frontend) |

잘 모르겠으면 셋 다 해도 된다.

### 이슈 하나 작업하기
```powershell
git switch -c feat/22-auth-개발용-가짜-로그인
```
- 브랜치 이름: `feat/<이슈번호>-<모듈>-<설명>` (CLAUDE.md 10장)
- 작업 → `pytest`, `npm test`, `npm run build` 통과 → 커밋 → push → **develop 대상 PR**
- PR이 머지되면 `git switch develop` → `git pull`로 돌아온다.

### 다른 사람 PR이 먼저 머지됐을 때 (내 브랜치에 반영)
```powershell
git switch develop
git pull
git switch -
git merge develop
```
- 다른 사람이 마이그레이션을 더했으면 내 마이그레이션의 `down_revision`을 고쳐야 할 수 있다 (`alembic heads`가 2개면). Claude에게 "develop 받았더니 alembic heads가 2개야, 고쳐 줘"라고 하면 된다.

## I. 자주 나는 오류

| # | 오류 메시지 (일부) | 원인과 해결 |
|---|---|---|
| 1 | `이 시스템에서 스크립트를 실행할 수 없으므로 ... Activate.ps1` | PowerShell이 스크립트를 막고 있다. **내 계정에만** 허용: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` → `Y`. 싫으면 cmd에서 `.venv\Scripts\activate.bat` |
| 2 | `'python'은(는) ... 인식되지 않습니다` 또는 Microsoft Store가 열림 | 설치 때 PATH 체크를 안 했다. Python을 다시 설치하며 "Add to PATH" 체크. 또는 `py -3.12 -m venv .venv` |
| 3 | `No module named 'app'` | `backend` 폴더가 아닌 곳에서 실행했다. `cd backend` 후 다시 |
| 4 | `No module named 'fastapi'` 등 | 가상 환경이 꺼져 있다. 줄 앞에 `(.venv)`가 있는지 보고 D-1의 활성화 명령 |
| 5 | `Access denied for user 'stageduck'@'localhost'` | `.env`의 비밀번호가 C단계와 다르다. 또는 C단계 GRANT를 빠뜨렸다 |
| 6 | `Unknown database 'stageduck'` | C단계의 `CREATE DATABASE`를 안 했다 |
| 6-1 | `Authentication plugin 'auth_gssapi_client' not configured` | Windows MariaDB는 **없는 계정**으로 접속하면 이렇게 답한다. C단계의 `CREATE USER`를 안 했거나 `.env`의 계정 이름이 틀렸다 |
| 7 | `Can't connect to MySQL server on 'localhost'` | MariaDB가 꺼져 있다. Windows 검색 → "서비스" → **MariaDB** 시작. (macOS `brew services start mariadb@11.4`, Docker `docker compose up -d mariadb`) |
| 8 | `UnicodeDecodeError: 'cp949' codec can't decode` | Windows 한글 인코딩 문제. PowerShell에서 `$env:PYTHONUTF8="1"` 후 다시. 계속 나면 시스템 환경 변수에 `PYTHONUTF8=1` 추가 |
| 9 | `Address already in use` / 포트 8000·5173 사용 중 | 이미 켜진 서버가 있다. 그 터미널에서 `Ctrl + C`. 못 찾겠으면 `uvicorn app.main:app --reload --port 8001` (이때 프론트 프록시는 8000이라 화면 API는 안 됨 → 원래 서버를 끄는 게 낫다) |
| 10 | `alembic ... Can't locate revision` | 다른 브랜치에서 만든 마이그레이션이 DB에 적용돼 있다. develop으로 돌아왔다면 그 브랜치에서 `alembic downgrade -1`을 먼저 하거나, 개발 DB를 지우고 다시 만든다 (`DROP DATABASE stageduck;` → C단계 → D-4). **개발용 DB에서만** |
| 11 | `npm ERR! ... EPERM` / `ENOENT` | 경로에 한글·공백이 있거나 백신이 막는다. 영어 경로로 옮기거나 `frontend\node_modules`를 지우고 `npm install` |
| 12 | `npm test`는 되는데 `npm run build`가 실패 | 타입 오류다. 메시지의 파일·줄을 Claude에게 보여 주고 고친다. `any`로 덮지 않는다 |
| 13 | `warning: LF will be replaced by CRLF` | 무시해도 된다. 저장소는 LF로 통일되어 있다 (`.gitattributes`) |
| 14 | 관리자 화면 로그인이 안 됨 | D-5에서 만든 계정인지 확인. 비밀번호를 잊었으면 HeidiSQL로 그 사용자를 지우고 D-5를 다시 |
| 15 | `git push` 할 때 권한 거부(403) | 초대를 수락하지 않았거나 다른 GitHub 계정으로 로그인돼 있다. B단계 1번 확인, `gh auth login` 또는 Windows 자격 증명 관리자에서 github.com 항목 삭제 후 다시 |
