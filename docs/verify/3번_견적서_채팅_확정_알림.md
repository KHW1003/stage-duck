## 1. 실행 방법

### 1.1 서버 켜기

**`APP_ENV=test`로 서버를 켜야 가짜 로그인(`POST /dev/switch-account`)이 켜져요.** 다른 값이면 `/dev` 라우터가 등록되지 않아서 0번 폴더의 계정 전환이 모두 `404`가 나요 (`main.py`, `get_settings().is_test_env`).

```bash
# backend 폴더에서
.venv\Scripts\activate
# backend/.env 에 APP_ENV=test 가 있는지 확인 (값을 여기에 옮겨 적지 않는다)
alembic upgrade head
python -m app.demo                 # 시드: 사용자 1명 + 업체 A~G (이미 있으면 건너뜀)
uvicorn app.main:app --reload      # http://127.0.0.1:8000
```

- 확인: http://127.0.0.1:8000/api/v1/health → `"env": "test"`
- 시드 계정에는 **비밀번호가 없어요.** 로그인은 `/auth/login` 대신 `/dev/switch-account {userId}`로 해요.

### 1.2 시드 계정 id 맞추기

컬렉션 변수의 기본값은 **빈 DB에 시드만 넣었을 때** 순서예요. 관리자 계정을 먼저 만들었거나 다른 데이터가 있으면 id가 달라요.

| 변수 | 계정 | 기본값 |
|---|---|---|
| `hostUserId` | 시연 사용자 `host@stageduck.test` (닉네임 광주밴드) | 1 |
| `supplierBUserId` | 업체 B `supplier-b@stageduck.test` (남의 리소스 404 확인용) | 3 |
| `supplierCUserId` | 업체 C `supplier-c@stageduck.test` (공간 C, 주 흐름) | 4 |

DB에서 `users` 표의 `id`, `email`을 보고 다르면 컬렉션 변수를 바꿔요.

### 1.3 Postman

1. Postman → **Import** → 위 컬렉션 파일
2. 컬렉션 **Variables**에서 `baseUrl`(`http://127.0.0.1:8000/api/v1`)과 계정 id를 확인해요
3. **3-12 사진 올리기**는 Body → form-data의 `file` 칸에서 png·jpg 하나를 직접 골라요 (Runner에서 고르지 않으면 3-12·3-13만 실패해요)
4. 컬렉션 **Run** → 0번 폴더부터 순서대로 돌려요. 앞 요청이 `performanceId`, `stageId`, `venueId`, `quoteId`, `roomId`, `confirmRequestId` 등을 변수에 담아요
5. 다시 돌릴 때는 0번부터 다시 돌려요 (새 요청서·새 공고가 생겨요). 같은 공고로 다시 보내면 4번 폴더는 이미 확정된 단계라서 `409`가 나요

**쿠키와 CSRF**: 로그인 쿠키(`access_token`, `refresh_token`, `csrf_token`)는 Postman 쿠키 저장소가 들고 있어요. 계정 전환 요청의 테스트 스크립트가 응답 쿠키 `csrf_token` 값을 `csrfToken` 변수에 담고, 모든 쓰기 요청(POST·PUT·DELETE)이 `X-CSRF-Token: {{csrfToken}}`을 보내요. `/dev/switch-account`는 CSRF 검사에서 빠져 있어요 (`auth/csrf.py`).

**확정 요청**: `4-11 확정하기`는 사전 스크립트에서 새 `idemKey`를 만들어 `Idempotency-Key`로 보내요. `4-12`는 같은 키로 다시 보내서 처음 결과가 그대로 오는지 봐요.

### 1.5 WebSocket (Postman 컬렉션에 넣지 못함)

`/ws`는 `/api/v1` 밖에 있고 받기 전용이에요. Postman v2.1 컬렉션 파일에는 WebSocket 요청을 담을 수 없어서 손으로 확인해요.

1. 브라우저 두 개(또는 일반 창 + 시크릿 창)로 http://localhost:5173 을 열어요. 한쪽은 사용자, 다른 쪽은 업체 C로 시연 계정 전환을 해요
2. 개발자 도구 → Network → **WS** → `/ws` 연결이 `101`인지 봐요
3. 업체가 메시지·사진을 보내면 사용자 쪽 Messages 탭에 `{"type":"message.created", ...}`가 오고, 화면에 새로고침 없이 말풍선이 생기는지 봐요 (AC-F3-08)
4. 사용자가 방을 열면 업체 쪽에 `message.read`가 오고 읽음 표시가 생기는지 봐요
5. 업체가 견적서를 고치면 `quote.updated`, 카드 상태가 바뀌면 `confirm.updated`가 오는지 봐요
6. 로그아웃한 창에서 `/ws`에 붙으면 `4401`로 닫히는지 봐요

Postman 앱에서 보려면: **New → WebSocket** → `ws://127.0.0.1:8000/ws`, Headers에 브라우저의 `Cookie` 값을 붙여요 (쿠키 값을 문서·PR에 옮겨 적지 않아요).
