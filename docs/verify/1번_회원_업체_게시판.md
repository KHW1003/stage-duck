## 1. 실행 방법

### 1.1 서버 켜기

**`APP_ENV=test`로 켜야 가짜 로그인(`POST /dev/switch-account`)과 비밀번호 찾기 시연 링크(`demoLink`)가 켜져요.**

```bash
# backend 폴더에서
.venv\Scripts\activate
# backend/.env 에 APP_ENV=test 가 있는지 확인 (값을 여기에 옮겨 적지 않는다)
python -m alembic upgrade head
python -m app.demo                 # 시드 (이미 있으면 건너뜀)
python -m uvicorn app.main:app --reload      # http://127.0.0.1:8000
```

### 1.2 시드 계정 id 맞추기

기본값은 **빈 DB에 시드만 넣었을 때** 순서예요. 다르면 컬렉션 변수를 바꿔요.

| 변수 | 계정 | 기본값 |
|---|---|---|
| `hostUserId` | 시연 사용자 (닉네임 광주밴드) | 1 |
| `supplierDUserId` | 업체 D (장비·설치·엔지니어 승인) | 5 |
| `testPassword` | 컬렉션이 만드는 시험 계정의 **가짜** 비밀번호 | `pm-duck-1234` |

### 1.3 Postman

1. Postman → **Import** → 위 컬렉션 파일 → **Variables**에서 `baseUrl`과 계정 id 확인
2. **Run** → 0번 폴더부터 순서대로. `0-1`이 실행마다 새 이메일·닉네임을 만들어서 **여러 번 돌려도 돼요** (2번 연속 실행해 확인)
3. 3번 폴더(간편 로그인)는 **네이버 서버를 부르지 않는** 요청만 있어요 (시작 302, state 불일치, 토큰 없음, 카카오 꺼짐)

- **CSRF**: 가입·로그인·계정 전환 응답의 쿠키 `csrf_token`을 `csrfToken` 변수에 담고, 상태를 바꾸는 요청이 `X-CSRF-Token`으로 보내요. `2-5`는 일부러 헤더 없이 보내 `403 CSRF_FAILED`를 확인해요.
- **바뀌는 데이터**: 실행마다 사용자 1명·업체 계정 1명·입점 신청 1건이 남고, 업체 D 소개 글은 쓰고 내려요(`DELETED`). 시연 DB 말고 시험용 DB에서 돌려요.
