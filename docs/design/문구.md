# 화면 문구: 오류·빈 화면·불러오기

> 초안 (2026-11-17, 해원). 팀 검토 전. 화면을 만들 때 이 문구를 그대로 쓰고, 바꾸면 이 문서도 같이 고친다.
> 모양: 목업 v4 `pages/error.html` (화면 전체 오류) · `pages/states.html` (빈 화면·입력 오류 등)
> 말투 규칙: DESIGN.md 7장 (화면은 해요체, 한 문장 40자 안팎, 엠대시 금지, "무엇이 잘못됐는지 + 무엇을 하면 되는지").
> 메일·사이트 알림·결제·청구·취소·담당표·약관·FAQ·이용 안내는 **합니다체** (11/19 팀 결정).

## 0. 어디에 무엇을 띄우나

| 상황 | 띄우는 곳 | 부품 (React) |
|---|---|---|
| 없는 주소, 401·403·404·500·503, 연결 끊김 (화면을 아예 못 그림) | 화면 전체 | `pages/ErrorPage.tsx` |
| 목록·구역 하나만 못 불러옴 | 그 구역 자리 | `shared/ui/LoadFail.tsx` |
| 400 `VALIDATION_FAILED` | 칸 아래 + 칸이 2개 이상이면 폼 맨 위에 모아서 | `FieldError.tsx` |
| 400 그 밖, 409, 422 (규칙·상태 충돌) | 그 버튼 근처 안내 상자 | `Notice.tsx` |
| 저장·전송 실패처럼 잠깐 알릴 것 | 오른쪽 아래 토스트 4초 | `Toast.tsx` |
| 목록이 비었음 | 목록 자리 | `EmptyState.tsx` |

- 서버가 준 `message`·`fieldErrors[].reason`이 있으면 그걸 쓰고, 없으면 아래 표의 기본 문구를 쓴다.
- 오류 번호(`requestId`)는 500일 때만 작게 보여 준다. 영어 오류 코드(`STAGE_NOT_OPEN` 등)는 화면에 쓰지 않는다.

## 1. 화면 전체 오류 (`error.html`)

| 코드 | 제목 | 설명 | 버튼 |
|---|---|---|---|
| 404 | 화면을 찾을 수 없어요 | 주소가 바뀌었거나, 지워졌거나, 볼 수 없는 화면이에요. 주소를 다시 확인해 주세요. | [홈으로] [이전 화면] |
| 401 | 로그인이 필요해요 | 로그인 시간이 지났거나 로그아웃됐어요. 다시 로그인하면 보던 화면으로 돌아와요. | [로그인] [처음으로] |
| 403 | 지금은 볼 수 없는 화면이에요 | 계정 종류가 다르거나, 업체 심사가 끝나지 않았거나, 이용이 정지된 계정이에요. 궁금한 점은 1:1 문의로 알려 주세요. | [홈으로] [1:1 문의] |
| 403 `ACCOUNT_SUSPENDED` | 이용이 정지된 계정이에요 | 경고가 3회 쌓여 공고·견적서·채팅을 쓸 수 없어요. (+ 정지일·마지막 경고·진행 중인 거래 표) | [1:1 문의] [로그아웃] |
| 500 | 서버에 문제가 생겼어요 | 잠시 후 다시 시도해 주세요. 결제 중이었다면 결제가 되었는지 결제 내역에서 먼저 확인해 주세요. | [다시 시도] [홈으로] |
| 503 | 잠시 점검하고 있어요 | 점검이 끝나면 바로 다시 쓸 수 있어요. 점검 시간은 공지사항에서 볼 수 있어요. | [다시 시도] |
| 연결 끊김 | 인터넷 연결이 끊겼어요 | 연결을 확인한 뒤 다시 시도해 주세요. 쓰고 있던 내용은 이 화면에 그대로 남아 있어요. | [다시 시도] |

- 404는 "없음"과 "남의 것이라 볼 수 없음"을 구분하지 않는다 (api-contract.md: 있는지조차 알리지 않음).
- 큰 번호는 주조색. 연결 끊김과 이용 정지는 번호 대신 아이콘.
- 홈은 계정에 따라: 사용자 `내 공연`, 업체 `공고`, 비로그인 메인.

## 2. API 오류 코드별 문구

`api-contract.md` 오류 코드 표 기준. 서버 `message`가 비어 있을 때 쓰는 기본 문구.

| 코드 | 띄우는 곳 | 문구 |
|---|---|---|
| `VALIDATION_FAILED` | 칸 아래 | 서버 `fieldErrors[].reason`. 위 요약: "확인할 칸이 N개 있어요" |
| `TOTAL_MISMATCH` | 합계 칸 아래 | 최종 합계가 항목 금액의 합과 달라요. 항목 금액을 확인하고 합계를 다시 계산해 주세요. |
| `TOTAL_TOO_LARGE` | 합계 칸 아래 | 금액이 너무 커요. 항목 금액을 다시 확인해 주세요. |
| `AMOUNT_MISMATCH` | 결제 버튼 위 | 청구 금액이 바뀌었어요. 새로 고친 뒤 금액을 확인하고 다시 결제해 주세요. |
| `UNDER_AGE` | 생년월일 칸 아래 | 만 14세 이상만 가입할 수 있어요. |
| `TERMS_REQUIRED` | 약관 묶음 아래 | 필수 약관에 모두 동의해 주세요. |
| `INVALID_BUSINESS_NO` | 사업자 번호 칸 아래 | 사업자 등록번호 10자리를 다시 확인해 주세요. |
| `UNAUTHENTICATED` | 화면 전체 401 | (1장 401) |
| `LOGIN_LOCKED` | 로그인 폼 위 | 비밀번호를 5번 틀려 잠시 잠겼어요. 잠시 후 다시 시도해 주세요. |
| `SUPPLIER_NOT_APPROVED` | 안내 상자 | 관리자 확인이 끝나면 쓸 수 있어요. 결과는 알림으로 알려 드려요. |
| `ACCOUNT_SUSPENDED` | 화면 전체 | (1장 이용 정지) |
| `POSTING_RATE_LIMITED` | 버튼 근처 | 너무 자주 올리고 있어요. 잠시 후 다시 올려 주세요. |
| `CHAT_NOT_STARTED` | 채팅 입력칸 | 업체가 견적서를 보내면 대화를 시작할 수 있어요. |
| `CATEGORY_NOT_APPROVED` | 안내 상자 | 승인받은 부문의 공고에만 견적서를 보낼 수 있어요. |
| `NOT_FOUND` | 화면 전체 404 / 구역이면 LoadFail | (1장 404) / 찾을 수 없어요. 지워졌거나 볼 수 없는 내용이에요. |
| `INVALID_STATE` | 안내 상자 | 지금 상태에서는 할 수 없어요. 새로 고친 뒤 다시 확인해 주세요. |
| `STAGE_NOT_OPEN` | 안내 상자 | 이 단계는 지금 견적서를 받고 있지 않아요. |
| `STAGE_ALREADY_CONFIRMED` | 안내 상자 | 이 단계는 이미 다른 견적서로 컨펌됐어요. |
| `VERSION_CONFLICT` | 안내 상자 + [새로 고침] | 그사이 내용이 바뀌었어요. 새로 고친 뒤 다시 해 주세요. |
| `CHECK_CONFLICT` | 안내 상자 (충돌 항목 목록) | 자동 검사에서 맞지 않는 항목이 있어요. 아래 항목을 업체와 조율해 주세요. |
| `OFFER_LIMIT` | 오퍼 버튼 근처 | 한 단계에 오퍼는 동시에 10곳까지 보낼 수 있어요. 답을 기다리거나 보낸 오퍼를 취소해 주세요. |
| `ACTIVE_POST_EXISTS` | 글쓰기 버튼 근처 | 이미 올라가 있는 게시글이 있어요. 그 글을 고치거나 내린 뒤 새로 써 주세요. |
| `ORDER_EXISTS` | 결제 버튼 위 | 이미 결제가 진행 중이에요. 결제 내역을 확인해 주세요. |
| `CONFIRM_REQUEST_STALE` | 카드 위 안내 + [새 버전 보기] | 견적서가 새 버전으로 바뀌었어요. 바뀐 내용을 확인한 뒤 다시 컨펌해 주세요. |
| `DETAIL_NOT_VIEWED` | 카드 위 | 견적서 내역을 먼저 열어 확인해 주세요. |
| `CONFIRM_REQUEST_EXPIRED` | 카드 위 | 확인 기한이 지난 카드예요. 업체에게 새 카드를 요청해 주세요. |

자주 쓰는 칸 문구 (`fieldErrors[].reason` 예시):

| 칸 | 문구 |
|---|---|
| 공연 날짜 | 공연 14일 전까지만 요청할 수 있어요. N월 N일 이후로 골라 주세요. |
| 예상 관객 수 | 1명부터 500명까지 적을 수 있어요. |
| 리허설 시작 | 리허설은 공연 시작보다 먼저여야 해요. |
| 엔지니어 작업 | 해 줘야 할 작업을 하나 이상 골라 주세요. |
| 최종 합계 | 금액을 다시 확인해 주세요. 견적서 합계는 10,000원 이상이어야 해요. |
| 업체할인 | 업체할인은 항목 합계(N원)보다 클 수 없어요. |
| 추가 요청 | 500자까지 쓸 수 있어요. |
| 필수 칸 공통 | (칸 이름)을 적어 주세요. / (칸 이름)을 골라 주세요. |

## 3. 빈 화면

모양: 아이콘 + "없어요" 한 줄 + 이유·할 일 한 줄 + 버튼 0~1개. 버튼은 그 화면을 채우는 다음 행동만.

| 화면 | 누구 | 제목 | 설명 | 버튼 |
|---|---|---|---|---|
| 내 공연 | 사용자 | 아직 준비 중인 공연이 없어요 | 요청서를 쓰면 공연장부터 차례로 업체 견적서를 받을 수 있어요. | [요청서 쓰기] |
| 견적함 | 사용자 | 아직 받은 견적서가 없어요 | 공고가 올라가 있어요. 업체가 견적서를 보내면 알림으로 알려 드려요. | [공간 보고 오퍼 보내기] |
| 공간 찾기 (결과 없음) | 사용자 | 조건에 맞는 공간이 없어요 | 고른 조건을 줄이거나 지역을 넓혀 보세요. | [조건 모두 지우기] |
| 관심 업체 | 사용자 | 관심 업체가 없어요 | 업체 프로필에서 하트를 누르면 여기에 모여요. | [PR 게시판 보기] |
| 알림 | 공통 | 새 알림이 없어요 | 견적서·오퍼·결제 소식이 오면 여기에 쌓여요. | - |
| 채팅 목록 | 공통 | 아직 대화가 없어요 | 업체가 견적서를 보내면 그 업체와 대화방이 열려요. | - |
| PR 게시판 | 공통 | 이 지역에 올라온 게시글이 없어요 | 지역이나 말머리를 바꿔 보세요. | [전체 지역 보기] |
| 공고 | 업체 | 지금 열린 공고가 없어요 | 내 부문·지역에 공고가 올라오면 알림으로 알려 드려요. | [업체 프로필 다듬기] |
| 받은 오퍼 | 업체 | 받은 오퍼가 없어요 | PR 게시글과 프로필을 본 사용자가 직접 오퍼를 보낼 수 있어요. | [PR 게시글 쓰기] |
| 내 PR 게시글 | 업체 | 아직 쓴 게시글이 없어요 | 게시글을 올리면 사용자가 보고 오퍼를 보낼 수 있어요. | [글쓰기] |
| 정산 예정 | 업체 | 정산 예정 금액이 없어요 | 공연이 끝나면 정산 예정 금액이 여기에 보여요. | - |
| 심사 대기 | 관리자 | 심사할 업체가 없어요 | 새 입점 신청이 오면 이 목록에 나타나요. | - |
| 신고 | 관리자 | 처리할 신고가 없어요 | 새 신고가 들어오면 이 목록에 나타나요. | - |

## 4. 불러오는 중·보내는 중

- 0.3초 안에 끝나면 아무것도 띄우지 않는다 (300ms 늦게 띄움). 깜빡임 방지.
- 목록·표: 그 모양대로 회색 막대(Skeleton). 빙글 도는 아이콘은 쓰지 않는다. 움직임 줄이기 설정이면 멈춘다.
- 버튼: 누르면 바로 다시 못 누르게 하고 글자를 바꾼다.

| 버튼 | 누른 뒤 |
|---|---|
| 견적서 보내기 | 견적서 보내는 중… |
| 결제하기 | 결제하는 중… (+ "끝날 때까지 화면을 닫지 마세요") |
| 컨펌 | 컨펌하는 중… |
| 저장 | 저장하는 중… |
| 게시 | 올리는 중… |

## 7. 명세 용어 → 화면 말 (2026-11-18)

명세·코드·DB·API 이름은 그대로 두고, **사용자가 보는 화면에만** 쉬운 말을 쓴다. 목업 v4는 이 표대로 바뀌어 있다.

| 명세·코드 | 화면 | 예시 |
|---|---|---|
| 컨펌 (사용자 버튼) | **[확정하기]** | 내역서·채팅 카드 버튼, "채팅에서 확정" |
| 컨펌됨 (CONFIRMED) | **확정** (상태) / **확정했어요** (문장) | 진행 바 "공연장 · 확정", 완료 화면 "장비를 확정했어요" |
| 컨펌하면 / 컨펌한 / 컨펌된 | 확정하면 / 확정한 / 확정된 | "확정하면 엔지니어 단계를 건너뛸지 물어봐요" |
| 견적 내역 확인 카드 (`confirm_requests`) | **최종 견적** | "업체 D가 최종 견적을 보냈어요. 내역서를 끝까지 보고 확정해 주세요." |
| 확인 카드 받음 (PENDING) | **최종 견적 도착** | 비교표 업체 칸 "● 최종 견적 도착" |
| 업체가 카드 보내기 | **[최종 견적 보내기]** | 업체 채팅 버튼 |
| 다시 조율 (RENEGOTIATE) | **[다시 이야기하기]** | 채팅 카드 버튼 |
| 카드 만료 (EXPIRED) | 최종 견적 기한 지남 | "최종 견적 기한이 지났어요. 업체에 다시 보내 달라고 하세요." |
| 조율 중 (NEGOTIATING) | **조율 중** (그대로) | |
| PR 게시판 (`pr_posts`) | **업체 찾기** | 머리 메뉴 "업체 찾기" |
| PR 게시글 | **소개 글** (업체 메뉴 "내 소개 글") | "소개 글을 올리면 업체 찾기에 보여요." |

- 알림 문구(`specs/notifications.md`)도 화면 글이므로 이 표를 따른다. 알림 type 이름(`CONFIRM_REQUESTED` 등)은 그대로.
- 결제 뒤 "섭외 확정"과 단계 "확정"은 같은 말을 쓴다. 헷갈리지 않게 결제 뒤에는 "섭외가 모두 확정됐어요(결제 완료)"처럼 결제를 함께 적는다.
