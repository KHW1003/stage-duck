## 1. 한 줄 소개

**공연을 열 장소를 고르고, 그 공간에 맞는 장비와 엔지니어를 순서대로 섭외해, 한곳에서 조율하고 한 번에 결제하는 소규모 공연 준비 플랫폼**

## 2. 해결하려는 문제

| 문제 | 지금의 불편 |
|---|---|
| 따로 찾아야 한다 | 공간·장비·엔지니어를 각각 검색하고, 같은 공연 조건을 업체마다 다시 설명한다 |
| 맞는지 모른다 | 공간을 찾아도 밴드 공연이 되는지, 장비가 들어가는지, 설치 시간이 맞는지 알기 어렵다 |
| 견적을 비교하기 어렵다 | 업체마다 포함 항목·금액 기준이 달라 같은 기준으로 비교할 수 없다 |
| 약속이 흔들린다 | 개인 연락으로 진행하면 노쇼·예약금 분쟁·조건 변경 기록이 남지 않는다 |

## 3. 해결 방법

1. **요청서 한 번** — 공연 기본 정보와 필요한 것(공연장·장비·엔지니어)을 한 번만 입력한다.
2. **순차 배정** — 공연장 → 장비 → 엔지니어 순서로 정한다. 장비 업체는 정해진 공연장 정보를, 엔지니어는 공연장·장비 정보를 보고 견적을 낸다.
3. **채팅 확정** — 업체 견적서를 받고 채팅으로 조율한 뒤, 업체가 보낸 견적 내역을 확인하고 컨펌한다.
4. **자동 검사** — 인원·입실·설치·리허설·철수 시간이 서로 맞는지 표시한다.
5. **한 번에 결제** — 모든 단계가 정해지면 통합 청구서로 한 번 결제한다. 결제금은 플랫폼이 보관하고 공연 후 정산한다 (모의).

## 4. 대상 사용자

| 사용자 | 설명 |
|---|---|
| 사용자 (주최자) | 전국, 관객 500명 이하 공연을 준비하는 인디 밴드, 소극단, 교회, 학원 등 |
| 업체 — 공연장 | 전문 공연장, 복합문화공간, 루프탑·정원·창고 등 공연 가능한 공간 운영자 |
| 업체 — 장비 | 음향 장비 대여, 운반, 설치·철수 업체 |
| 업체 — 엔지니어 | 현장 음향 운영을 맡는 음향 엔지니어 (프리랜서 포함) |
| 관리자 | 업체 입점 심사, 신고·경고·정지, 거래 이력 확인 |

대표 시연: 광주, 관객 80명 밴드 공연 (토요일 19~21시, 리허설 17시)

## 5. 핵심 흐름

```
요청서 작성 → 공고 게시
 → ① 공연장: 견적서(러브콜/오퍼) → 채팅 → 견적 내역 확인 → 컨펌 → [다음 단계로]
 → ② 장비:   (공연장 정보 공유) 견적서 → 채팅 → 컨펌 → [다음 단계로]   ※ 공연장에 있으면 건너뜀
 → ③ 엔지니어: (공연장·장비 정보 공유) 견적서 → 채팅 → 컨펌             ※ 포함돼 있으면 건너뜀
 → 통합 청구서 → 결제(모의 보관) → 섭외 확정 → 최종 담당표(연락처 공개) → 공연 완료 → 정산 예정
```

## 6. 차별점

- **한 플랫폼에서 공간·장비·인력을 모두** 해결한다.
- **순서대로 확인**하기 때문에 시간은 조금 걸려도 확실하다 (공간 조건을 본 업체가 견적).
- **합의 기록과 결제**가 플랫폼 안에 남아 노쇼·분쟁에 대응할 수 있다.
- 가격과 조건 확인 상태를 따로 보여준다. 싸다고 가능한 것이 아님을 보여준다.

> 경쟁 서비스에 이런 기능이 전혀 없다고 주장하지 않는다. 실제 수요와 수수료 수용성은 별도 검증 대상이다.

## 7. MVP 범위

| 포함 (MVP) | 제외 (후속) |
|---|---|
| 사용자 가입 (이메일·네이버, 카카오는 비활성) | 리얼 후기, 업체 → 사용자 평가 |
| 업체 3단계 입점·관리자 심사 | 익스프레스 (유료 상단 노출) |
| 공간·서비스 등록, 공간 탐색 | 채팅 이모티콘 |
| 요청서 STEP1·STEP2, 공고, 버전 관리 | 실결제·실정산·실제 위약금 청구 |
| 순차 배정, 직접 오퍼(동시 10곳), 관심 업체 | 전자계약, 메일·문자 알림 |
| 견적서(업체당 여러 개), 실시간 채팅, 견적 내역 확인·컨펌 | 외부 업체 재고·달력 연동 |
| 자동 검사, 기술 확인 기록 | 버스킹 장비 대여·배송 |
| 통합 청구서, 에스크로형 모의 결제, 취소·위약금 계산 | AI 자동 구성 추천 |
| PR 게시판, 반려 카운트, 신고·경고(3회 정지) | 업체 담당자 여러 명 계정 |
| 관리자: 심사, 신고·제재, 거래 이력, 시연 데이터 초기화 | 국세청 사업자 조회 연동 |

## 8. 수익 구조 가설

- 주 수익: 성사된 거래에 대한 **업체 중개 수수료** (통합 청구서에 수수료 표시). 요율은 미정.
- 후속: 익스프레스(유료 상단 노출), 반복 이용 업체 대상 견적·일정 관리 구독.
- 포트폴리오 단계에서는 기술 동작과 역할별 업무 흐름을 입증한다. 실제 사업성은 별도 검증한다.
