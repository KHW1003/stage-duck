## 1. SDD 단계별 역할 (일정표 기준)

| 역할 | Day 1 원칙·범위 | Day 2 스펙 | Day 3 계획 | 담당자 |
|---|---|---|---|---|
| **A** | 사용자·문제 정의, 사용자 스토리 | 스펙 총괄, 수용 기준(GWT) 통일, 범위 밖 명시 | 스펙↔계획 추적표 | |
| **B** | 기술 제약 정리 | F1 회원·인증, F4 콘텐츠·상호작용 스펙 | 아키텍처, API 계약, 인증 방식 | |
| **C** | 기술 제약 정리 | F2 기본 자원, F3 관계·참여, F5 부가 기능 스펙 | 데이터 모델 (ERD, 테이블, 제약조건) | |
| **D** | 주요 화면 목록, 참고 UI 조사 | 유저 플로우, Figma 와이어프레임 착수 | 와이어프레임 완성, 컴포넌트·라우팅 | |
| 전원 | 킥오프, 원칙 작성 | 스펙 리뷰, 모호점 해소 | — | 전원 |

## 2. 기능 영역 담당 (구현 단계, 화면 → API → DB → 권한 → 테스트 끝까지)

| 영역 | 포함 기능 (요구사항 ID) | 담당자 |
|---|---|---|
| 1. 공연 요청·배정 | REQ, ASSIGN, OFFER, 공간 탐색(SPACE-03) | |
| 2. 업체·견적·게시판 | SUP, SPACE 등록, QUOTE, BOARD | |
| 3. 채팅 확정 (전담, D-20) | CHAT, 자동 검사(CHK), 기술 확인(TECH) | |
| 4. 결제·운영 | PAY, POL, ADMIN | |
| 공통 | AUTH, DEMO, 공통 화면·오류 형식 | 전원 |

> 채팅을 한 명이 전담하기로 했으므로(D-20) 3번 영역에 채팅이 들어간다. 자동 검사·기술 확인은 채팅 확정과 붙어 있어 같은 영역에 두었다 (제안).

## 4. 배정할 때 고려할 점

- 각자 익숙한 언어·프레임워크 (기술 스택 결정과 연결)
- 채팅 전담자는 실시간 통신 경험이 있으면 유리
- B(API)와 C(데이터 모델)는 Day 3에 계속 맞춰야 하므로 소통이 쉬운 조합으로
- D(화면)는 Day 2부터 유저 플로우를 받아야 하므로 A와 바로 붙어서 작업
