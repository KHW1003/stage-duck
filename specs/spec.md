## 0. 공통

### 0.1 기능 묶음

| 묶음 | 이름 | 포함 영역 (명세서 ID) | 사용자 스토리 |
|---|---|---|---|
| **F1** | 회원·인증 | AUTH, SUP | US-01 ~ 08 |
| **F2** | 기본 자원 — 공간·서비스·요청서·견적서 | SPACE-01·02, SUP-04, REQ-01~04, QUOTE | US-09 ~ 17 |
| **F3** | 관계·참여 — 순차 배정·채팅 확정·오퍼·검사 | ASSIGN, CHAT, OFFER, CHK, TECH | US-18 ~ 28 |
| **F4** | 콘텐츠·상호작용 — PR 게시판·신고·반려 카운트 | BOARD, POL | US-29 ~ 34 |
| **F5** | 부가 기능 — 탐색·프로필·결제·관리 | SPACE-03, REQ-05, PROFILE, PAY, ADMIN, DEMO | US-35 ~ 43 |

> 결제(PAY)는 F5에 둔다 (Q-OPEN-1 확정). spec의 F1~F5는 **문서 묶음**이고, 개발 담당 묶음(1~4)은 [roles.md](roles.md)를 따른다.

### 0.2 공통 규칙
- 역할: 방문자 / 사용자 / 업체(심사 중·승인) / 관리자. 한 계정은 한 역할.
- 권한·금액·상태 변경은 서버에서 검사한다. 권한이 없는 데이터는 존재 여부도 알 수 없게 한다.
- 시간은 KST, 분 단위. 금액은 원 단위 정수, 부가세 포함.
- 요청서·견적서는 수정할 때마다 새 버전을 만든다. 컨펌·결제 시점의 조건은 스냅샷으로 보관한다.
- 모든 화면에 "포트폴리오 시뮬레이션 — 실제 거래가 아닙니다"를 표시한다.

### 0.3 시연 데이터 (수용 기준에서 쓰는 값)

|---|---|

| 공연장 C | 50만 원, 장비 설치 가능 15:00 |
| 장비 D | 125만 원, 설치 90분, 엔지니어 포함 (수정 후 135만 원, 15:45 완료) |
| 장비 E | 확인 필요 항목이 남은 견적 |
| 엔지니어 F·G | 단독 견적 |

## F1. 회원·인증

### 목적
사용자는 빠르게 가입하고, 업체는 검증을 거쳐 들어오며, 모든 회원은 자기 데이터만 본다.

### 기능
| ID | 기능 | 우선순위 |
|---|---|---|
| FR-AUTH-01 | 사용자 이메일 가입 (이름, 전화번호, 이메일, 생년월일, 닉네임, 비밀번호, 가입 목적 등. 주소 받지 않음) | 필수 |
| FR-AUTH-02 | 네이버 가입·로그인 (개발 중 테스트 계정) | 필수 |
| FR-AUTH-03 | 카카오 가입·로그인 (기능은 만들고 기본 꺼짐) | 권장 |
| FR-AUTH-04 | 소셜 가입 후 추가 정보·우리 약관 동의 | 필수 |
| FR-AUTH-05 | 소셜 계정 연결 규칙 (같은 이메일 자동 병합 금지) | 필수 |
| FR-AUTH-06 | 로그인·로그아웃, 역할별 첫 화면 | 필수 |
| FR-AUTH-07 | 역할 기반 접근 제한 | 필수 |
| FR-AUTH-08 | 시연 계정 전환 (테스트 환경만) | 권장 |
| FR-SUP-01~03 | 업체 3단계 입점: 계정(이메일만) → 사업자 정보 → 관리자 심사 | 필수 |

### 수용 기준

**사용자 가입**
- **AC-F1-01** Given 가입 화면에서, When 필수 항목(이름·이메일 등) 하나를 비우고 가입하면, Then 가입되지 않고 그 칸에 이유가 표시된다.
- **AC-F1-02** Given 필수 항목과 필수 약관만 채웠을 때, When 마케팅 수신에 동의하지 않고 가입하면, Then 가입이 완료된다.
- **AC-F1-03** Given 생년월일이 만 14세 미만일 때, When 가입하면, Then 가입되지 않는다.
- **AC-F1-04** Given 테스터로 등록된 네이버 계정이 있을 때, When 네이버로 로그인하면, Then 처음이면 추가 정보 화면으로, 가입되어 있으면 내 공연 화면으로 이동한다.
- **AC-F1-05** Given 네이버 동의 화면에서 선택 항목(생일 등)을 해제했을 때, When 추가 정보 화면에서 직접 입력하면, Then 가입이 완료된다.
- **AC-F1-06** Given 소셜에서 이름·이메일을 받아왔을 때, When 추가 정보 화면이 열리면, Then 그 값이 미리 채워져 있고 수정할 수 있다.
- **AC-F1-07** Given 추가 정보 화면에서, When 우리 서비스 약관에 동의하지 않고 완료를 누르면, Then 가입이 완료되지 않는다.
- **AC-F1-08** Given 카카오 로그인이 꺼져 있을 때, When 카카오 로그인 요청을 직접 보내면, Then 거부되고 화면에 카카오 버튼도 없다.
- **AC-F1-09** Given 카카오 로그인을 켜고 테스트 계정이 있을 때, When 카카오로 로그인하면, Then 가입·로그인된다.
- **AC-F1-10** Given 이메일 `a@x.com`으로 가입한 계정이 있을 때, When 같은 이메일의 네이버 계정으로 로그인하면, Then 기존 계정에 자동으로 들어가지 않는다.

**로그인·권한**
- **AC-F1-11** Given 사용자·업체·관리자 계정이 있을 때, When 각각 로그인하면, Then 내 공연 / 공고 목록(승인 전에는 심사 상태) / 심사 대기 화면이 각각 열린다.
- **AC-F1-12** Given 로그인한 뒤 로그아웃했을 때, When 브라우저 뒤로 가기를 누르면, Then 이전 화면의 개인 정보가 보이지 않는다.
- **AC-F1-13** Given 사용자 X가 로그인했을 때, When 사용자 Y의 공연·채팅방 ID로 조회하면, Then 찾을 수 없다는 응답을 받는다.
- **AC-F1-14** Given 업체 D가 로그인했을 때, When 업체 E의 견적서 ID로 조회하면, Then 거부된다.
- **AC-F1-15** Given 심사 중인 업체가, When 견적서 전송 요청을 직접 보내면, Then 거부된다.
- **AC-F1-16** Given 운영 설정으로 실행했을 때, When 시연 계정 전환 화면·요청에 접근하면, Then 보이지도 동작하지도 않는다.

**업체 입점**
- **AC-F1-17** Given 입점 신청 2단계에서, When 사업자 유형으로 "개인(프리랜서)"을 고르면, Then 사업자등록번호·등록증 칸이 사라진다.
- **AC-F1-18** Given 사업자등록번호를 입력할 때, When 체크섬이 틀린 번호를 저장하면, Then 저장되지 않고 이유가 표시된다.
- **AC-F1-19** Given 심사 중인 업체가 있을 때, When 관리자가 승인하면, Then 업체에게 3단계 서비스 등록과 공고 목록이 열린다.
- **AC-F1-20** Given 관리자가 사유를 적어 반려했을 때, When 업체가 로그인하면, Then 반려 사유가 보이고 고쳐서 다시 신청할 수 있다.

### 범위 밖
국세청 사업자 상태 조회, 업체 담당자 여러 명 계정, 업체의 소셜 로그인.

## F2. 기본 자원 — 공간·서비스·요청서·견적서

### 목적
업체는 자기 공간·서비스를 등록하고, 사용자는 공연 조건을 한 번만 입력하며, 업체는 그 조건을 보고 견적서를 보낸다.

### 기능
| ID | 기능 | 우선순위 |
|---|---|---|
| FR-SUP-04 | 업체 서비스 등록 (부문, 활동 지역, 소개, 장비 분류, 설치·철수 시간, 신뢰 지표는 선택) | 필수 |
| FR-SPACE-01 | 공간 등록 (수용 인원, 입실·퇴실, 대관료, 기본 장비·인력, 공간 조건) | 필수 |
| FR-SPACE-02 | 확정된 공연의 공간 조건 보존 (스냅샷) | 필수 |
| FR-REQ-01 | 요청서 STEP1 공연 기본 정보 (공연 3일 전까지) | 필수 |
| FR-REQ-02 | 요청서 STEP2 필요한 것 (공연장·장비·엔지니어 토글, 업체 제안 받기, 엔지니어 작업 7개) | 필수 |
| FR-REQ-03 | 공고 게시 (현재 단계 부문 업체 + 지역 필터, 컨펌 시 자동 마감) | 필수 |
| FR-REQ-04 | 요청서 수정과 버전 | 필수 |
| FR-QUOTE-01 | 공고 목록·상세 (업체) | 필수 |
| FR-QUOTE-02 | 견적서 작성·전송 (업체당 여러 개, 부가세 포함, 풀스펙 표시) | 필수 |
| FR-QUOTE-03 | 견적서 수정 (버전) | 필수 |

### 수용 기준

**공간·서비스**
- **AC-F2-01** Given 공간 등록 화면에서, When 수용 인원에 501을 넣고 저장하면, Then 저장되지 않는다.
- **AC-F2-02** Given 공간 등록 화면에서, When 퇴실 마감을 입실 시각보다 빠르게 넣으면, Then 저장되지 않는다.
- **AC-F2-03** Given 공간 C(기본 마이크 2개)로 확정된 공연이 있을 때, When 업체가 C의 기본 마이크를 1개로 바꾸면, Then 확정된 공연에는 2개로 남아 있다.

**요청서**
- **AC-F2-04** Given STEP1에서, When 예상 관객에 0 또는 501을 넣으면, Then 저장되지 않는다.
- **AC-F2-05** Given STEP1에서, When 리허설 시작을 공연 시작보다 늦게 넣으면, Then 저장되지 않는다.
- **AC-F2-06** Given 오늘이 11/12일 때, When 공연 날짜를 11/14로 넣으면, Then 저장되지 않는다 (3일 이후부터 가능).
- **AC-F2-07** Given STEP1에서, When "토요일 19~21시, 80명, 리허설 17시, 광주"를 입력하면, Then 저장된다.
- **AC-F2-08** Given STEP2에서, When 장비 토글을 "이미 있어요"로 끄면, Then 장비 입력 칸이 사라지고 이 공연에는 장비 단계가 생기지 않는다.
- **AC-F2-09** Given STEP2 장비 칸을 처음 열었을 때, When 화면을 보면, Then 미리 들어 있는 장비가 하나도 없다.
- **AC-F2-10** Given 엔지니어가 "필요해요"일 때, When 작업을 하나도 고르지 않고 다음을 누르면, Then 넘어가지 않고 이유가 표시된다.

**공고**
- **AC-F2-11** Given 공연장·장비·엔지니어가 모두 필요한 공고를 게시했을 때, When 장비 업체·엔지니어가 공고 목록을 보면, Then 이 공고가 보이지 않는다 (공연장 업체에게만 보인다).
- **AC-F2-12** Given 공고가 게시되었을 때, When 심사 중인 업체가 공고 목록을 보면, Then 보이지 않는다.
- **AC-F2-13** Given 장비 단계까지 컨펌된 공연이 있을 때, When 사용자가 리허설을 17:00 → 16:00로 바꾸면, Then 요청서 v2가 생기고 v1이 남으며, 컨펌된 장비 업체에게 재확인 요청이 간다.

**견적서**
- **AC-F2-14** Given 업체 D가 로그인했을 때, When 공고 상세·목록 어디를 보아도, Then 다른 업체가 보낸 견적서는 보이지 않는다.
- **AC-F2-15** Given 장비 단계가 열린 공고에서, When D가 "추가 마이크 2, 밴드 음향, 설치·철수, 엔지니어 포함, 125만 원, 설치 90분" 견적서를 보내면, Then 사용자 견적함에 도착하고 알림이 간다.
- **AC-F2-16** Given 같은 단계에서, When D가 기본형·고급형 견적서 2개를 보내면, Then 두 견적서가 각각 따로 보인다.
- **AC-F2-17** Given 견적서를 보낼 때, When 항목 합과 다른 최종 합계를 보내면, Then 거부된다.
- **AC-F2-18** Given 공연장 단계가 아닌 공고에, When 공간 견적서를 보내면, Then 거부된다.
- **AC-F2-19** Given 공연장 업체 A가 장비·엔지니어 포함으로 체크했을 때, When 견적서를 보내면, Then "풀스펙" 표시가 붙는다.
- **AC-F2-20** Given D 견적서 v1(125만)이 있을 때, When D가 135만으로 수정하면, Then v2가 생기고 v1 기록이 남는다.

### 범위 밖
장비 표준 품목 목록(장비는 자유 입력), 외부 재고·달력 연동, 버스킹 장비 대여.

## F3. 관계·참여 — 순차 배정·채팅 확정·오퍼·검사

### 목적
공연장 → 장비 → 엔지니어 순서로, 앞에서 정해진 조건을 본 업체와 채팅으로 조율하고, 견적 내역을 확인해 컨펌한다.

### 기능
| ID | 기능 | 우선순위 |
|---|---|---|
| FR-ASSIGN-01 | 단계 진행 (엄격한 순차) | 필수 |
| FR-ASSIGN-02 | 단계별로 업체에게 앞 단계 정보 전달 | 필수 |
| FR-ASSIGN-03 | 풀스펙 공연장·"전부 구했어요" 건너뛰기 (책임 고지) | 필수 |
| FR-CHAT-01 | 채팅방, 사용자만 채팅 시작, 실시간, 사진·파일·읽음 | 필수 |
| FR-CHAT-02 | 채팅 카드 (견적서 / 견적 내역 확인 / 컨펌 완료 / 안내) | 필수 |
| FR-CHAT-03 | 견적 내역 확인 카드와 컨펌 (48시간, 버전 고정, 단계당 하나) | 필수 |
| FR-CHAT-04 | [다음 단계로] (모집 시작 / 건너뛰기 / 통합 결제하기) | 필수 |
| FR-CHAT-05 | 다른 견적서 자동 마감 (반려 카운트 제외) | 필수 |
| FR-CHAT-06 | 연락처·외부 거래 경고, 결제 전 연락처 비공개 | 필수 |
| FR-OFFER-01~03 | 직접 오퍼 (열린 단계만, 동시 10곳), 오퍼 응답, 관심 업체 저장 | 필수 |
| CHK, FR-CHK-01 | 단계별 자동 검사, 단계별 견적 비교 화면 | 필수 |
| FR-TECH-01 | 기술 확인 (항목은 엔지니어 재량) | 필수 |

### 수용 기준

**순차 배정**
- **AC-F3-01** Given 공연장 단계가 아직 컨펌되지 않았을 때, When 장비 업체가 공고 목록을 보면, Then 이 공고가 보이지 않는다.
- **AC-F3-02** Given 사용자가 공연장 C를 컨펌했을 때, When [다음 단계로] → [장비 업체 모집 시작]을 누르면, Then 장비 업체의 공고 목록에 이 공고가 나타난다.
- **AC-F3-03** Given 장비 단계가 열렸을 때, When 장비 업체가 공고 상세를 보면, Then 배정된 공연장 C의 입실 시각·기본 장비·전원 정보가 보인다.
- **AC-F3-04** Given 사용자가 "전부 구했어요"를 눌렀을 때, When 재확인 팝업에서 확인하면, Then 남은 단계가 `건너뜀`이 되고 책임 고지 동의가 기록된다.
- **AC-F3-05** Given 풀스펙 공연장 A의 견적서를 컨펌했을 때, When [다음 단계로] 화면이 열리면, Then 장비·엔지니어 단계 건너뛰기를 제안한다.

**채팅 확정**
- **AC-F3-06** Given 업체가 견적서를 보냈지만 사용자가 [채팅 시작]을 누르지 않았을 때, When 업체가 메시지를 보내려 하면, Then 보낼 수 없다.
- **AC-F3-07** Given 다른 사람의 채팅방이 있을 때, When 그 채팅방 ID로 접근하면, Then 열 수 없다.
- **AC-F3-08** Given 채팅방이 열려 있을 때, When 업체가 메시지·사진을 보내면, Then 사용자 화면에 새로고침 없이 나타나고, 사용자가 읽으면 업체 화면에 읽음 표시가 된다.
- **AC-F3-09** Given 업체가 v1 견적서로 [견적 내역 확인] 카드를 보냈을 때, When 업체가 견적서를 v2로 수정하면, Then v1 카드의 [컨펌]이 비활성화되고 "새 견적이 있어요" 안내가 뜬다.
- **AC-F3-10** Given 견적 내역 확인 카드를 받았을 때, When 내역서를 열지 않고 [컨펌]을 누르려 하면, Then 눌리지 않는다.
- **AC-F3-11** Given 같은 단계에 업체 B·C의 확인 카드가 있을 때, When 두 탭에서 B와 C를 동시에 컨펌하면, Then 하나만 성공한다.
- **AC-F3-12** Given 확인 카드를 보낸 지 48시간이 지났을 때, When 사용자가 카드를 보면, Then `만료`로 표시되고, 업체는 새 카드를 다시 보낼 수 있다.
- **AC-F3-13** Given 공연장 C를 컨펌했을 때, When 같은 단계의 A·B 업체가 화면을 보면, Then "다른 업체와 진행하기로 했어요" 알림이 있고, 사용자의 반려 카운트는 오르지 않는다.
- **AC-F3-14** Given 마지막 필요 단계를 컨펌했을 때, When 컨펌 완료 카드를 보면, Then [다음 단계로] 대신 [통합 결제하기]가 나온다.
- **AC-F3-15** Given 결제 전 채팅에서, When 전화번호나 계좌번호 형태의 글을 보내면, Then 플랫폼 밖 거래 경고가 표시된다.

**직접 오퍼**
- **AC-F3-16** Given 공연장 단계가 열려 있을 때, When 사용자가 장비 업체의 PR 게시글을 보면, Then [오퍼 보내기]가 비활성화되고 [관심 업체 저장]만 할 수 있다.
- **AC-F3-17** Given 같은 단계에서 10곳에 오퍼를 보냈을 때, When 11번째 오퍼를 보내면, Then 막힌다.
- **AC-F3-18** Given 업체가 오퍼를 받았을 때, When 견적서를 보내면, Then 사용자 견적함에 "내가 오퍼한 업체" 표시와 함께 나타난다.
- **AC-F3-19** Given 장비 업체를 관심 업체로 저장해 두었을 때, When 장비 단계가 열리면, Then "저장한 업체에 오퍼할까요?" 안내가 뜬다.

**자동 검사·비교**
- **AC-F3-20** Given 공연장 단계에 A(풀스펙 400만)·B(40만, 설치 가능 17:00)·C(50만, 설치 가능 15:00) 견적서가 있을 때, When 비교 화면을 열면, Then A는 "풀스펙" 배지, B는 `경고` "설치 시간 0분", C는 `통과`(120분)로 한 화면에 보인다.
- **AC-F3-21** Given 공연장 C가 정해진 장비 단계에서, When D(설치 90분) 견적서를 검사하면, Then 설치 완료 16:30 ≤ 리허설 17:00이므로 `통과`다.
- **AC-F3-22** Given 공연장 B가 정해진 장비 단계라면, When D 견적서를 검사하면, Then 설치 완료 18:30 > 17:00이므로 `충돌` "90분 늦음"이고 컨펌할 수 없다.
- **AC-F3-23** Given D 견적서에 엔지니어가 포함되어 있을 때, When 엔지니어 단계로 가려 하면, Then `경고`와 함께 엔지니어 단계 건너뛰기를 제안한다.
- **AC-F3-24** Given C+D가 `통과`였을 때, When 리허설을 16:00으로 바꾸면, Then D가 다시 검사되어 `충돌`이 되고, D가 15:45 완료로 수정하면 다시 `통과`가 된다.

**기술 확인**
- **AC-F3-25** Given 엔지니어(또는 엔지니어 포함 장비 업체 D)가 확인 항목을 정했을 때, When 공연장 C와 D가 답변하면, Then 각자 자기 담당 항목에만 답변할 수 있다.

### 범위 밖
오퍼 전용 비공개 공고, 채팅 이모티콘, 장비 수량 자동 검사, 소리 크기·호환성·안전 자동 판정.

## F4. 콘텐츠·상호작용 — PR 게시판·신고·반려 카운트

### 목적
업체는 먼저 자신을 알리고, 사용자는 업체를 둘러보며, 규칙을 어기는 회원은 걸러진다.

### 기능
| ID | 기능 | 우선순위 |
|---|---|---|
| FR-BOARD-01~03 | PR 게시판 (한 목록 + 말머리, 지역·말머리 필터, 승인 부문만 작성, 부문당 1개, 연락처 금지, 블라인드, 정지 업체 글 숨김) | 필수 |
| FR-POL-02 | 반려 카운트 (채팅 후 5회 / 미채팅 10회 → 24시간 대기, 180일 후 초기화) | 필수 |
| FR-POL-03 | 단골 표시 (이용 N번) | 권장 |
| FR-POL-04 | 신고 → 관리자 확인 → 경고, 3회면 정지 | 필수 |

### 수용 기준
- **AC-F4-01** Given 음향 장비 부문만 승인된 업체가, When PR 게시글을 쓰면서 `[공연장]` 말머리를 고르려 하면, Then 고를 수 없고 서버도 거부한다.
- **AC-F4-02** Given 업체가 장비 탭에 활성 게시글 1개가 있을 때, When 장비 탭에 새 글을 올리면, Then 막힌다.
- **AC-F4-03** Given PR 게시글을 쓸 때, When 본문에 전화번호·계좌번호·외부 링크를 넣으면, Then 경고가 표시되고, 신고되면 관리자가 블라인드하며 그 업체에 경고 1회가 기록된다.
- **AC-F4-04** Given 방문자가, When PR 게시판을 열면, Then 로그인 없이 게시글을 볼 수 있다.
- **AC-F4-05** Given 사용자가 채팅을 시작한 뒤 공고를 내린 것이 5회일 때, When 새 공고를 게시하면, Then 마지막으로 내린 시각 + 24시간 이후에만 게시된다.
- **AC-F4-06** Given 마지막 반려가 180일 전일 때, When 사용자의 반려 카운트를 보면, Then 0이다.
- **AC-F4-07** Given 업체가 공고 목록을 볼 때, When 사용자 닉네임을 보면, Then 옆에 반려 횟수와 이용 횟수가 표시된다.
- **AC-F4-08** Given 업체가 경고를 2회 받았을 때, When 관리자가 세 번째 경고를 주면, Then 계정이 정지되고 견적서를 보낼 수 없다.
- **AC-F4-09** Given PR 게시판에 공연장·장비·엔지니어 글이 섞여 있을 때, When 방문자가 부문 필터를 `[엔지니어]`로 바꾸면, Then 엔지니어 말머리 글만 보이고, `[전체]`로 돌리면 모두 보인다.
- **AC-F4-10** Given 업체의 장비 글이 블라인드되었을 때, When 그 업체가 장비 말머리로 새 글을 올리면, Then 막히고, 관리자가 블라인드를 해제한 뒤에는 수정·재게시할 수 있다.
- **AC-F4-11** Given 업체가 정지되었을 때, When 누구든 PR 게시판을 열면, Then 그 업체의 글이 보이지 않고, 정지가 풀리면 다시 보인다.

### 범위 밖
리얼 후기·평점, 익스프레스, 업체 → 사용자 평가.

## F5. 부가 기능 — 탐색·마이페이지·결제·관리

### 목적
누구나 공간을 찾아보고, 사용자는 진행 상황을 한눈에 보며, 모든 단계가 정해지면 한 번에 결제한다.

### 기능
| ID | 기능 | 우선순위 |
|---|---|---|
| FR-SPACE-03 | 공간 탐색 (지역·인원·유형·조건 필터) | 필수 |
| FR-REQ-05 | 내 공연 현황 (단계, 다음 할 일) | 필수 |
| FR-PROFILE-01 | 업체 프로필 (누구나, 연락처 비공개) | 필수 |
| FR-PROFILE-02 | 개인 프로필 (관계있는 업체만, 이름·연락처 비공개) | 필수 |
| FR-PAY-01 | 통합 청구서 (플랫폼 이용료 5% 별도 표시) | 필수 |
| FR-PAY-02 | 자체 에스크로형 모의 결제 (보관 → 정산 예정) | 필수 |
| FR-PAY-03 | 취소 수수료·위약금 (결제 전 10%, ~D-3 10%, D-2 50%, D-1 70%, D-0 100%) | 필수 |
| FR-PAY-04 | 섭외 확정·최종 담당표 (연락처 공개) | 필수 |
| FR-ADMIN-01~04 | 심사, 거래 이력, 신고·경고·정지, 게시글 블라인드·해제 | 필수 |
| FR-DEMO-01~02 | 시연 데이터, 초기화 (테스트 환경만) | 필수 |

### 수용 기준
- **AC-F5-01** Given 방문자가, When 광주 / 80명 / 밴드 공연 가능으로 공간을 필터하면, Then 시연 공간 A·B·C가 나오고 수용 인원 80명 미만 공간은 나오지 않는다.
- **AC-F5-02** Given 공연장은 컨펌, 장비는 조율 중일 때, When 사용자가 내 공연을 보면, Then "공연장 확정 ✓ → 장비 조율 중 (견적 2건) → 엔지니어 대기"처럼 단계와 다음 할 일이 보인다.
- **AC-F5-03** Given 공연장 C(50만)·장비 D(135만)가 컨펌되고 엔지니어는 건너뜀일 때, When 통합 청구서를 열면, Then 업체 금액 185만 원, 플랫폼 이용료 9만 2,500원(5%), 합계 194만 2,500원이 표시된다.
- **AC-F5-04** Given 아직 컨펌되지 않은 단계가 있을 때, When 통합 청구서를 요청하면, Then 만들어지지 않는다.
- **AC-F5-05** Given 결제 화면에서, When 금액을 조작한 결제 요청을 보내면, Then 거부된다.
- **AC-F5-06** Given 결제가 성공했을 때, When 같은 성공 응답이 한 번 더 오면, Then 결제 기록은 하나이고, 결제 버튼을 두 번 빠르게 눌러도 한 번만 결제된다.
- **AC-F5-07** Given 결제가 끝났을 때, When 결제 상태를 보면, Then 결제금이 `보관 중`이고, 공연 완료 후에는 업체별 `정산 예정`으로 바뀐다.
- **AC-F5-08** Given 업체 금액 185만 원(이용료 포함 194만 2,500원)을 결제한 공연에서, When D-1에 사용자가 취소하면, Then 업체 금액의 70%(129만 5,000원)가 위약금으로 C·D에 금액 비율대로 배분되고, 나머지 55만 5,000원이 환불 예정액으로 표시된다 (플랫폼 이용료는 환불하지 않음).
- **AC-F5-09** Given 모든 단계가 컨펌된 뒤 결제 전에, When 사용자가 취소하면, Then 취소 수수료 10%가 확정 업체들에게 금액 비율로 배분된다.
- **AC-F5-10** Given 결제한 공연에서, When 업체 사정으로 취소되면, Then 사용자에게 플랫폼 이용료까지 전액 환불되고 그 업체에 경고 1회가 기록되며, 사용자는 그 단계만 다시 모집할 수 있다.
- **AC-F5-11** Given 결제가 끝났을 때, When 사용자·C·D가 최종 담당표를 보면, Then 같은 일정·담당 범위와 서로의 연락처가 보이고, A·B·E는 볼 수 없다.
- **AC-F5-12** Given 결제 전일 때, When 업체가 사용자 정보를 보면, Then 연락처는 보이지 않는다.
- **AC-F5-13** Given 시연 시나리오를 진행했을 때, When 관리자가 거래 이력을 보면, Then 모든 상태 변경이 시간순으로 보인다.
- **AC-F5-14** Given 운영 설정일 때, When 시연 데이터 초기화를 요청하면, Then 동작하지 않는다.
- **AC-F5-15** Given 방문자가, When 업체 프로필을 열면, Then 상호·승인 부문·소개·PR 게시글·"거래 n건"이 보이고 전화번호·사업자 서류는 보이지 않는다.
- **AC-F5-16** Given 업체가 사용자의 공고를 보고 있을 때, When 사용자 닉네임을 누르면, Then 닉네임·프로필 사진·가입일·이용 횟수·반려 횟수가 보이고 이름·전화번호·이메일·생년월일은 보이지 않는다.
- **AC-F5-17** Given 공고·오퍼·채팅으로 만난 적 없는 업체가, When 사용자 프로필 주소로 직접 들어가면, Then 404로 막힌다.

### 범위 밖
실결제·실정산·실제 위약금 청구, 결제 후 내용 변경·추가 결제, 메일·문자 알림.
