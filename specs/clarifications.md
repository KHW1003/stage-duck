| Q-03 | 다음 단계 공고는 언제 열리나? | 컨펌 후 사용자가 **[다음 단계로]** 를 누를 때 | 자동으로 넘기면 건너뛰기를 고를 기회가 없음 (제안서 11/12, D-1) |
| Q-04 | 앞 단계 확정 전에 다음 단계 업체가 미리 볼 수 있나? | 불가 — 엄격한 순차 | 팀 원칙 (D-2) |

| Q-06 | 오퍼를 보내면 공고를 비공개로 할 수 있나? | 안 됨. 공고는 항상 공개 | MVP 단순화 (D-25) |
| Q-07 | 공고는 누구에게 보이나? | 현재 단계 부문의 모든 승인 업체 + 업체가 지역 필터 | 순차 배정과 일치 (D-4, 11/12 확인) |
| Q-08 | 공고(단계 모집)는 언제 마감되나? | 그 단계에서 컨펌하면 자동 마감 | D-5 |
| Q-09 | 공연 며칠 전까지 요청할 수 있나? | 3일 전까지 | D-16 |
| Q-10 | 리얼 후기·익스프레스를 MVP에 넣나? | **둘 다 후속.** 규칙은 미리 정해 둠 (후기 작성 30일·수정 7일) | 채팅·순차 배정이 우선 (D-3, D-13, D-23) |

## 2. 견적·채팅

| ID | 질문 | 결정 | 근거·날짜 |
|---|---|---|---|
| Q-12 | 업체가 한 단계에 견적서를 몇 개 보낼 수 있나? | 여러 개 (기본형 / 고급형 등). 컨펌은 하나만 | D-6 |
| Q-13 | 누가 채팅을 시작하나? | **사용자만.** 업체는 먼저 걸 수 없음. 시작 시점이 "컨택" | 원치 않는 연락 방지 (제안서) |
| Q-14 | 채팅에 무엇을 보낼 수 있나? | 텍스트, 카드, 사진, 파일, 읽음 표시. 이모티콘은 후속 | D-7 |
| Q-15 | 채팅은 실시간인가? | 실시간 | 채팅이 필수 흐름이라 사용성 차이가 큼 (D-7b) |
| Q-16 | "확정"은 어떻게 하나? | 업체가 **견적 내역 확인 카드**(버전 고정)를 보냄 → 사용자가 내역서를 끝까지 보고 **컨펌** | 무엇에 동의했는지 분명히 (제안서) |
| Q-17 | 확인 카드 기한은? | 48시간. 지나면 만료, 업체가 다시 보낼 수 있음 | D-22 |
| Q-18 | 다른 업체를 골라 자동 마감된 견적은 반려 카운트에 넣나? | 넣지 않음 | 정상적인 비교·선택 (D-21) |
| Q-19 | 공연장 단계에서 풀스펙과 공간만 견적을 어떻게 구분하나? | 업체가 견적서에 **"풀스펙"을 명시** → 배지 표시 | D-8 |
| Q-20 | 견적 금액에 부가세는? | 포함 금액으로 통일 | D-14 |

## 3. 검사·현장 확인

| ID | 질문 | 결정 | 근거·날짜 |
|---|---|---|---|
| Q-21 | 장비 수량을 자동으로 비교하나? | **안 함.** 장비는 자유 입력, 사용자가 견적서를 보고 판단 (CHK-06 삭제) | 표준 품목 목록을 만들지 않기로 함 (자문 11/12) |
| Q-22 | 공연장 단계에서 설치 시간 부족을 어떻게 아나? | 공연장 견적서에 **"장비 설치 가능 시작 시각"** 을 받아, 리허설까지 남은 시간을 표시 (CHK-02) | 시연 "B는 리허설을 놓친다"를 공연장 단계에서 보여주기 위함 (11/12) |
| Q-23 | 기술 확인 항목은 무엇인가? | 고정 목록 없음. **엔지니어 재량**으로 정해 기록 (참고 항목 제공) | 현장 판단은 엔지니어 몫 (자문 11/12) |
| Q-24 | 엔지니어에게 맡길 작업은? | 메인 음향, 설치·철수 보조, 사운드체크·리허설 진행(동행 시), 모니터 믹싱, 무선 마이크 채널, 녹음·스트리밍(추가금), 장비 문제 대응 + 직접 입력 | D-17 |
| Q-25 | 신뢰 지표(보험, 공연장 등록, 자격)는? | 모두 선택 입력. 책임은 업체 | 자문 11/12 |

## 4. 결제·취소·제재

| Q-26 | 결제는 업체별로? 한 번에? | 모든 단계 확정 후 **통합 청구서로 한 번** | "한 번에 해결" 차별점 (D-9). 업체별 결제(목산 의견)는 채택 안 함 |
| Q-27 | 결제는 어떻게 구현하나? | **자체 에스크로형 모의 결제** (보관 → 공연 후 정산 예정 → 취소 시 자동 배분) | 노쇼 방지·위약금을 한 구조로 보여줌 (D-10). 실제 돈은 움직이지 않음 |
| Q-28 | 수수료를 보여주나? | 통합 청구서에 표시 | 투명성 (D-18) |
| Q-29 | 결제 전(모두 확정 후) 취소하면? | 취소 수수료 10%, 확정 업체들에게 금액 비율로 배분 | D-12 |
| Q-30 | 결제 후 ~ D-3 취소는? | 10% | D-12 |
| Q-31 | D-2 / D-1 / D-0 취소는? | 위약금 50% / 70% / 100%, 업체에 귀속 | 회의 11/11 |
| Q-32 | 업체 사정으로 취소되면? | 사용자 전액 환불 + 업체 경고 1회 | D-12 |
| Q-33 | 플랫폼 밖 거래는 어떻게 막나? | 채팅 연락처·계좌 경고 + 결제 전 연락처 비공개 + 신고 | D-11 |
| Q-34 | 신고 후 처리는? | 관리자 확인 → 경고. **경고 3회면 이용 정지** (사용자·업체 모두) | 11/12 |
| Q-35 | 반려 카운트는 언제 없어지나? | 마지막 반려 후 180일 지나면 0 | D-19 |
